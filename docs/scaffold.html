Given an antibody–antigen complex — or a lone antigen, from which the epitope is predicted off the structure — design protein scaffolds that present the epitope in its native, antibody-binding conformation. Pipeline: RFdiffusion3 → backbone pre-filter → ProteinMPNN → AlphaFold3 → scoring.

This page is a planning simulation. It does not run designs. It shows the cluster job that would be submitted and estimates throughput from the project's measured DP4 enrichment rates; the per-design rows below are illustrative, not completed predictions. The selected structure is a real PDB shown in 3D (drag to rotate). To stage a real job, upload a structure and set a Backend URL (see foot of page); the design itself then runs on the cluster.

Design protocol

Set the options for each step. The run and the Gemini job below update to match.

1 Generate backbones — RFdiffusion3
0.00
−1 … 0 (neutral) … +1, intended to bias away from or toward helical scaffolds. Not yet wired into generation, so the control is disabled; it is shown to mark a planned option.
Each epitope earns its exploitation budget by improving round over round (adaptive).
2 Backbone clash pre-filter — AOMclash
3 Sequence design — ProteinMPNN
Epitope positions are held fixed, so the epitope keeps its native identity.
4 Fold — AlphaFold3

Single-sequence, seed 1, no MSA: tests whether the design folds with the epitope in native geometry without template or coevolution cues. No options.

5 Score & select
  
Blank = simulated demo. With the cluster service tunneled (see foot of page), uploading a structure and running stages a real job on the cluster and returns its submit script.
Backend staging applies to uploaded structures; the built-in example targets always run the simulated demo.
With no Backend URL this simulates a run (illustrative numbers). With a Backend URL and an uploaded structure it prepares real design inputs on the cluster; the design still runs there.

How this becomes a real server. This page is a static frontend — it runs the same whether served from GitHub Pages or opened locally. To route a job to Gemini it would call a small backend API (FastAPI/Flask) on a cluster-access host, which submits RFdiffusion3 → backbone pre-filter → ProteinMPNN → AlphaFold3 and reports back. runJob() in this page can swap its simulated result for a fetch() to that API.
