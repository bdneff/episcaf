Select epitopes

Read the methods

Choose one of two routes based on your starting structure.

Contact epitopeImplemented

Antigen residues within the configured heavy-atom distance of the antibody define the contact epitope. The default reference configuration uses a 4 Å cutoff.

The selected residues are compiled into contig specifications for RFdiffusion3. A target can contain several sequence segments that are adjacent in the folded antigen; the specifications describe the fixed segments and the regions to be generated.

One complex can yield more than one target (labeled 0P, 1P, …), each scaffolded separately. The contig constrains residues within a segment more tightly than the geometry between segments.

In: antibody–antigen complex (PDB). → Out: the epitope — the antigen residues the antibody contacts.

Candidate surface regionsImplemented

growPatch generates candidate surface regions by neighbor-based growth, fills short sequence gaps, filters by the configured size and sequence-segment limits, and removes near-duplicates. The candidates are then ranked by total DiscoTope score (generation and ranking are separate steps). Selected candidates are converted into design specifications for scaffold generation.

  • 1Surface. Relative solvent accessibility per residue (freesasa, Tien-2013 normalization); residues exposing ≥ 20% of their type’s area (relSASA ≥ 0.2) are “surface.”
  • 2Grow. From each surface residue, accrete the nearest connected surface residues to footprint size (~16). This produces conformational (sequence-discontinuous) patches.
  • 3Clean up. Gap-fill short sequence gaps, keep patches large enough (≥12 residues) and not too fragmented (≤3 sequence segments, or “islands”). The gap-filled ranges are the segments sent to scaffold design.
  • 4Dedupe. Jaccard non-max suppression removes near-duplicates (overlap ≥ 0.8), keeping the one with fewer segments, then the larger.
  • 5Rank. Candidates are ranked by their total DiscoTope-3.0 score (summed over the candidate's residues), normalized within the antigen; summing rewards larger high-likelihood patches. When scores are unavailable the full candidate set is shown unranked.

Each surviving candidate becomes an episcaf contig string handed to the same contig machinery as the known-antibody arm.

In: antigen structure (one chain, PDB). → Out: a set of candidate surface regions, each a residue set that could be an antibody footprint.

Validation

The sampling method is parity-verified: on chain A of 8PWW it reproduces the reference implementation for the tested input and configuration. Benchmarked on 117 conformational SAbDab epitopes (a candidate counts as recovered at Jaccard overlap ≥ 0.8 with a reference epitope), neighbor-based growth reaches recall@0.8 ≈ 0.80. The surface cutoff is SASA_CUT = 0.2. A directional-sampling method and its higher union recall are recorded in ENUMERATOR_DECISION.md but are off by default. Staging a full no-antibody design run end-to-end through the tool is in development.

Generate scaffolds

Read the methods

Steps run in order. Iterative refinement loops selected designs back into backbone generation.

Backbone generationImplemented

RFdiffusion3 generates backbone structures using the fixed epitope segments and the contig specification. The default configuration requests eight backbones per contig.

The contig fixes the epitope residues and their order but leaves the rest of the fold free, so each backbone is a different way of presenting the same epitope. The backbone coordinates are passed to sequence design. Runs as a SLURM array on the cluster.

In: epitope residues held fixed (a contig spec on the antigen). → Out: de novo backbone(s) presenting that epitope — coordinates, no sequence yet.

Implementation

hpc/sbatch/rfd3_array.sbatch
Backbone obstruction filterIn development

Each generated backbone is scored with AOMclash before sequence design. Candidates are ranked separately for each epitope, and the configured retention rule determines which backbones continue to ProteinMPNN and AlphaFold 3.

For example, retaining 50% of 20 backbones sends the 10 lowest-scoring candidates to the next stage. Retention can be set as a percentage or as a score cutoff. The score is the same AOMclash score used at final evaluation, applied here to the bare backbone. Runs cluster-side, where the backbones live.

In: generated backbones and the reference epitope. → Out: the backbones retained for sequence design.

Implementation

scripts/aomclash_prefilter.py · episcaf_analysis/aomclash/score.py
Sequence designImplemented

ProteinMPNN generates amino-acid sequences for the retained backbones while preserving the specified epitope residues. The default configuration requests eight sequences per backbone.

The epitope keeps its native identity while the rest of the scaffold is redesigned. The *_fixed.pdb naming contract carries the epitope-fix information to the next stage.

In: a backbone. → Out: amino-acid sequence(s) for it.

Implementation

stage03_mpnn_fixed_pdbs · stage03_mpnn_submit
Structure predictionImplemented

AlphaFold 3 predicts a structure for each designed sequence. The predicted structure is compared with the design and reference epitope to calculate the structural metrics.

The documented configuration uses single-sequence input (a self-only MSA), templates disabled, and seed 1. AF3 produces the structures everything downstream scores; it does not measure stability or experimental binding.

In: a designed sequence (with antigen/epitope context). → Out: predicted structure + confidence/metrics (pLDDT, PAE, RMSD, clash counts).

Implementation

stage04_af3_emit_jsons · af3_array.sbatch
Iterative refinementPlanned

The controller selects designs from the current round and uses partial diffusion to generate variants: a good backbone is re-noised part-way and denoised again with the epitope fixed. Subsequent rounds include both these variants and independently generated backbones. The allocation between the two sources changes according to score improvement, and a cap on the partial-diffusion allocation preserves sampling from new backbones.

Diversity. Repeated refinement can concentrate candidates within a narrow structural family. Independently generated backbones are retained to support broader sampling.

Evaluate designs

Read the methods
Structural metricsImplemented

The predicted structure is aligned to the reference using the specified epitope alignment. Metrics include structural deviation, prediction confidence, and antibody obstruction.

Epitope RMSD measures backbone deviation from the reference epitope; overall RMSD measures deviation from the intended (MPNN-designed) structure over the comparison region; epitope PAE reports confidence at the epitope. Geometric clashes are calculated against the reference antibody when one is available; otherwise the selected AOMclash estimate (aomclash_pred) supplies the obstruction metric.

In: each AF3 structure, aligned to the reference on the epitope. → Out: the per-design metrics — epitope & overall RMSD, epitope PAE, antibody clashes, AOMclash.

Implementation

stage05_extract_metrics
AOMclashIn development

AOMclash reads an antibody-occupancy map at the scaffold atoms after alignment to an epitope-centered frame. The raw occupancy sum (s_p1_free) includes atoms more than 4 Å from the reference antigen; higher values indicate more scaffold material in antibody-occupied regions. See the AOMclash documentation for the map, score, and calibration.

The deployed scorer uses the single occupancy-sum feature. A multi-feature model comparison is documented separately. The score is used in the supported backbone-filtering and final-ranking stages, with raw and calibrated outputs identified separately. The map is vendored in-repo, so the scorer runs offline.

In: a design's scaffold atoms, framed on the epitope. → Out: the raw occupancy sum s_p1_free, and a calibrated clash-scale output where applied.

  • ✓Map. Vendored (aom_map.pkl); occupancy peaks about 14 Å out along the outward normal (a measured map property).
  • ✓Scorer. score.py frames a design (PDB or AF3 CIF) and returns s_p1_free; parity-checked against the reference extractor.
  • •Final ranking wired. The twelvemer preset uses aomclash_pred for accessibility. In development: the backbone-filtering stage and its cluster-side validation.

Ranking and selectionImplemented

The selected preset specifies the metrics, transformations, and weights used in the composite score. Designs are ranked within each epitope group, and the requested number is selected. The binding model can provide an alternative ranking where the required features are available.

Each preset targets an input mode: antibody_softgate uses the measured AF3 clash count against the reference antibody; twelvemer is the no-antibody mode and uses the AOMclash estimate. The composite renormalizes its weights over whichever metric columns are present.

The binding model is a separate ranker: L2-regularized logistic regression on structural and epitope features, fit to the DP4 assay data (grouped-by-epitope cross-validated ROC-AUC 0.817). It provides a binding score and is selectable in the results viewer; the composite score does not include it.

In: per-design metrics and a preset. → Out: designs ranked by composite score, then the per-epitope top-k selected. The binding model provides an alternative ranking.

Export the library

Read the methods
Library preparationImplemented

Selected sequences are assembled and encoded as DNA using the configured oligo encoder and codon weights. The output is a DNA order file for the selected vendor.

Case encoding, component concatenation, and vendor-specific formatting are in the implementation (the LadnerLab oligo encoder with the DP3 codon weights). Dated example: the DP4 library (2026) shipped at 36,000 constructs.

In: the selected designs. → Out: a DNA order file for the selected vendor.
