When the antigen has a solved antibody–antigen complex, the epitope is already known: it is the set of antigen residues the antibody contacts (4 Å cutoff). No prediction needed — this is the ground-truth setting where we know exactly where “good” is.

Those contact residues are compiled into RFdiffusion3 contigs, which fix the epitope residues’ identity and sequence order. One complex can yield more than one patch (0P, 1P, …); each patch is a separate target. A patch is in turn one or more islands — spatially contiguous runs — and the contig constrains residues within an island far more tightly than the geometry between islands, which is the known multi-island failure mode.

In: antibody–antigen complex (PDB). → Out: the epitope — the antigen residues the antibody contacts.

In the code

stage01_compile_contigs · stage02_emit_rfd3_inputs

With no antibody there is no known epitope. growPatch does not predict the single most likely one; that is the task of epitope predictors such as DiscoTope and BepiPred, which rank how antibody-like each surface residue is and return a predicted epitope. growPatch instead samples candidate surface patches across the antigen, for coverage rather than a single call, so the candidates can be scaffolded and ranked downstream. It replaces the old tiled 12-mer approach, which (being sequence-linear) could not propose a conformational epitope.

  • 1Surface. Relative solvent accessibility per residue (freesasa, Tien-2013 normalization); residues exposing ≥ 20% of their type’s area (relSASA ≥ 0.2) are “surface.”
  • 2Two sampling methods. Neighbor-based patch growth (seed & grow) — from a surface residue, accrete the nearest connected surface residues to footprint size (~16). Directional surface sampling (antibody’s-eye view) — sample approach directions and take the surface cap an antibody from each direction would contact. Both produce conformational (sequence-discontinuous) patches.
  • 3Clean up. Gap-fill, keep patches large enough (≥12 residues) and not too fragmented (≤3 sequence segments, or “islands”).
  • 4Combine & dedupe. Merge both methods and apply Jaccard non-max suppression; a patch found by both methods is tagged as such (provenance, not on its own a confidence claim). How much overlap is kept is set by the dedup threshold and an optional cap.
  • 5Optional ranking layer. A DiscoTope-style per-residue score can prioritize the list when compute is limited; it sits on top of the sampled set.

Each surviving patch becomes a candidate epitope (an episcaf contig string) handed to the same contig machinery as the known-antibody arm.

In: antigen structure (one chain, PDB). → Out: a set of candidate surface patches, each a residue set that could be an antibody footprint.

Status. The sampling method is implemented and parity-verified: on chain A of 8PWW it reproduces the reference implementation for that input and configuration (227 identical candidate patches). Benchmarked on 117 conformational SAbDab epitopes, neighbor-based growth and directional sampling perform comparably alone and are complementary, so the default combines them (recall@0.8 = 0.92 versus ~0.80 for either alone). The surface cutoff is settled at SASA_CUT=0.2, and the interactive patch viewer is live. Still being brought up: staging a full no-antibody design run end-to-end through the tool.

episcaf_analysis/growpatch/{core,read,eyeview}.py · results/growpatch/ENUMERATOR_DECISION.md · ref: segmentation/growPatch.py

Generate de novo protein backbones that hold the epitope in its native geometry, 8 per contig. This is the first point where a real 3-D scaffold exists.

The contig fixes the epitope residues and their order but leaves the rest of the fold free, so each backbone is a different way of presenting the same epitope. Runs as a SLURM array on the cluster.

In: epitope residues held fixed (a contig spec on the antigen). → Out: de novo backbone(s) presenting that epitope — coordinates, no sequence yet.

In the code

hpc/sbatch/rfd3_array.sbatch

A cheap gate right after backbone generation: score each RFd3 backbone with AOMclash and keep only the least-clashy per epitope — before spending MPNN and AF3 on a design whose scaffold mass sits where the antibody has to bind. The biggest compute win in the pipeline.

It is the same AOMclash score used at the end, applied early (on the bare backbone instead of the AF3 model). The epitope’s place in each backbone is read from its contig; keep rule is a best-fraction-per-epitope or a cutoff. Cluster-side (backbones live on the cluster).

In: RFd3 backbones + the epitope frame. → Out: the subset of backbones kept — those whose epitope stays sterically accessible, by keep-frac.

Assign an amino-acid sequence to each backbone with the epitope positions held fixed, 8 sequences per backbone, so the epitope keeps its native identity while the scaffold is free to be whatever folds.

The *_fixed.pdb naming contract carries the epitope-fix information to the next stage.

In the code

stage03_mpnn_fixed_pdbs · stage03_mpnn_submit

Fold each designed sequence to check whether it actually adopts the intended structure with the epitope in native geometry. Single-sequence prediction, seed 1, no MSA / data pipeline.

AF3 produces the structures everything downstream scores. It tests whether a design folds as intended; it does not measure stability or binding.

In: a designed sequence (with antigen/epitope context). → Out: predicted structure + confidence/metrics (pLDDT, PAE, RMSD, clash counts).

In the code

stage04_af3_emit_jsons · af3_array.sbatch

Rather than one pass, the best designs of a round seed the next: re-noise a good backbone part-way and denoise it with the epitope fixed (a partial-diffusion child, a neighbor of something that worked). A controller picks winners each round, splits the next round’s budget between fresh de-novo designs and children, and stops an epitope on success, a score plateau, or a round cap.

Design decision: adaptive budget. The open question — are children genuinely better or just best-of-N in a lucky basin? — is handled by letting each epitope earn its children budget: start de-novo-only and raise the children share with a streak of round-over-round improvement. The data decides per epitope instead of a fixed guess.

In the code

episcaf_pipeline/ipd.py (controller) · ipd_driver.py · scripts/ipd_round.py

From each AF3 structure, aligned to the native complex by an epitope Kabsch fit, extract the numbers a design is judged on.

Epitope RMSD and overall RMSD (did the fold hold the epitope / hold together), epitope PAE (confidence at the epitope), AF3 clashing-residue count (real accessibility where an antibody exists), and AOMclash (aomclash_pred) as the no-antibody accessibility metric — the learned successor that has replaced the native-aware cylinder (kept only for before/after).

In: each AF3 structure, aligned to the native complex on the epitope. → Out: the per-design metrics — epitope & overall RMSD, epitope PAE, AF3 clash, AOMclash.

In the code

stage05_extract_metrics

Replaces the geometric native-aware cylinder as the no-antibody accessibility metric. It reads an antibody occupancy map (built from ~1,029 SAbDab complexes, antibody geometry only, so it is AlphaFold-version agnostic) at each scaffold atom. We ship a single interpretable number — s_p1_free, the occupancy summed over the scaffold atoms that stick into antibody territory beyond the native antigen — rather than a 111-feature gradient-boosted bank.

Why one feature: the carved occupancy sum is ~0.87–0.89 on its own and the full model only ~0.02 higher — not worth ~38 correlated features and the overfitting risk. It is used in both places accessibility matters: the backbone pre-filter (cheap early gate) and the final composite (the no-antibody accessibility term). The map is vendored in-repo, so the scorer runs offline.

In: a design's scaffold atoms, framed on the epitope. → Out: s_p1_free — occupancy summed over the free atoms, an accessibility score in AF3-clash units.

  • ✓Map. Vendored (aom_map.pkl), verified physical (occupancy peaks ~14 Å out on the antibody side).
  • ✓Scorer. score.py frames a design (PDB or AF3 CIF) and returns s_p1_free; parity-checked against the reference extractor.
  • ✓Scorer wired into the composite. The twelvemer preset scores accessibility with aomclash_pred. Still in progress: the backbone pre-filter stage and cluster-side training/validation against the cylinder on matched folds.

In the code

episcaf_analysis/aomclash/ (aom_map, score, features) · results/aomclash/feature_set_decision.md

Combine the metrics into one score and pick the designs to ship. The composite is column-driven: it renormalizes its weights over whichever metric columns are present, so swapping the cylinder for aomclash_pred on the no-antibody arm is a one-key change, no engine edit.

It ranks designs rather than applying a hard gate, then takes the per-epitope top-k. The weights and transforms are dials in presets.py, with a preset per regime (antibody_softgate keeps the real AF3 clash; twelvemer is the no-antibody arm, now AOMclash-scored).

Beyond the geometric composite, an interpretable binding model (L2-logistic on a small, inspectable feature set; grouped-by-epitope CV ROC-AUC ~0.81) gives a binding score used to rank designs and is a selectable ranker — built on the DP4 assay data, with the bound-state dynamics features dropped for cleaner static ones after a held-out check.

In: per-design metrics (with binding_pred where features exist), plus a preset. → Out: designs ranked by composite score, then the per-epitope top-k selected.
